# 6회차 — Claude Code 의 네이티브 GUI

- 작성일: 2026-08-13
- 방향 확정: **Claude Code 를 실행해 명령을 내리되, 사람이 보는 화면은 우리 앱 UI 다.**

## 앞선 두 방향이 왜 아니었나

- **1~4회차(앱이 spawn + 채팅)**: 방향은 맞았으나 UI 가 클로드 앱을 닮은 채팅이었다
- **5회차(관측기 + 앱 안 터미널)**: 입구를 터미널로 옮겼더니 사람이 보는 것이 CLI 의 TUI 가
  됐다 — 환영 배너·상태줄·박스 그림이 전부 남의 화면이라 우리가 손댈 수 없다

이번 회차의 정의: **CLI 는 엔진이고 화면은 우리 것이다.** TUI 는 어디에도 뜨지 않는다.

## 구조

```
사람 → 대화 판(우리 UI) → agent-host(spawn, stream-json) → claude
                        ← 차례·도구 활동·권한 질문·자식 ←
```

- `electron/agent-host.ts` — `claude -p --input-format stream-json --output-format stream-json
  --verbose --permission-prompt-tool stdio --forward-subagent-text --append-system-prompt <말투>`.
  cwd 는 사람이 고른 프로젝트. worktree 격리는 걷어냈다 (사람이 지켜보며 대화하는 자리이므로)
- `model/conversation.ts` — 화면이 그리는 것은 터미널 출력이 아니라 **차례**다: 누가 말했고,
  그 차례에 어떤 도구를 썼는가. 한 턴이 여러 문단으로 와도 말풍선은 하나, 도구를 쓴 뒤의
  말은 새 차례 (TDD 7개)
- `model/use-agent.ts` — stream-json → 대화·자식 타일. 첫 말이 프로세스를 띄운다
  (사람은 "실행" 을 따로 누르지 않는다)
- `widgets/conversation` — 대화 판: 사람의 말은 왼쪽 선, 에이전트의 말은 본문, 도구 활동은
  그 아래 조용한 줄. 권한 질문은 작성창 자리를 대신하는 카드(허용 / 이 세션에선 항상 허용 / 거부)
- 서브에이전트는 기존 타일 그대로 — 대화 판이 기둥, 자식이 곁 (`observatoryLayout`)

## 검증 (2026-08-13, CDP 실기)

우리 입력창에 한 문장 → `Bash find …` 도구 활동이 대화에 흐르고, 서브에이전트 타일이
오른쪽에 갈라져 자기 일감을 보였다. 권한 질문은 우리 카드로 두 번 떴고 "항상 허용" 으로
껐다. API 529(과부하)도 에이전트의 말로 화면에 실렸다 — CLI 화면은 한 번도 보이지 않았다.

## 첫 실행 플로우 (2026-08-13, 2차)

빠져 있던 것: 처음 켠 사람이 지나야 하는 문 — 로그인, 일할 자리, 권한 모드. 우리 UI 는
바로 대화부터 열었고, 로그인이 없으면 첫 말에 그냥 실패했다.

**로그인은 CLI 의 것이다.** `claude auth status --json` 이 상태를 주고(실측: loggedIn·email·
orgName), `claude auth login` 이 브라우저를 연다. 우리는 묻고·띄우고·다시 묻을 뿐 자격 증명을
만지지 않는다 — 만지는 순간 우리가 보안 경계가 된다. `claude` 를 못 찾으면(ENOENT) 설치 안내.

**세 단계 카드** (`widgets/setup`): 계정 → 일할 프로젝트 → 어디까지 맡길까요.
끝난 단계는 체크, 남은 단계는 번호 (색은 안 들인다). 모델은 접힌 자리에.

**권한 모드는 사람이 정한다** (`model/run-config.ts`, TDD):

| 모드 | 인자 |
|---|---|
| 물어보기 | `--permission-prompt-tool stdio` (우리 카드로 승인) |
| 편집은 자동 | `--permission-mode acceptEdits` + 위 창구 |
| 전부 허용 | `--dangerously-skip-permissions` (묻는 창구를 **떼어낸다** — 함께 주면 CLI 가 거부) |

로그인과 프로젝트가 갖춰지기 전에는 대화 판을 열지 않는다. 갖춰진 사람에게는 이 화면이
아예 보이지 않는다 (실측: 기존 프로필은 바로 대화, 새 프로필은 이 화면).

## 고르기 전에 시작해 버리는 문제 (2026-08-13, 3차)

증상: "새로고침해도 내가 고르기도 전에 시작해버린다".

원인: 관문을 **프로젝트가 기억돼 있는가**로 판단했다. 프로젝트가 남아 있으면 곧장 대화가
열려, 권한 모드를 고를 기회 자체가 없었다. 게다가 고른 값은 화면 상태라 껐다 켜면 사라졌다.
"기억된 프로젝트가 있다" 와 **"이 설정으로 시작하겠다"** 는 다른 말이다.

- `model/settings.ts` — `{permissionMode, model, setupDone}`. 되읽을 때 모르는 값은 기본으로
  되돌린다 (손상된 파일이 "전부 허용" 으로 켜지지 못하게). TDD 4개
- `electron/settings-store.ts` — userData 의 파일 하나. 렌더러는 디스크를 만지지 않는다
- 관문은 이제 셋이다: 로그인 ∧ 프로젝트 ∧ **setupDone**. 설정을 읽는 동안에는 아무 화면도
  열지 않는다 — 기본값으로 먼저 그리면 한 프레임이 거짓말을 한다
- 타이틀바에 **설정** — 언제든 되돌아가 다시 고른다

검증: 첫 화면이 설정 → "편집은 자동" 고르고 시작 → 대화 열림 → **새로고침해도 대화가
유지되고** 저장된 값은 `{permissionMode: acceptEdits, setupDone: true}`.

## 화면 언어 (2026-08-13, 4차 — 프론티어 패스)

크기 말고는 위계가 없었고, 기억에 남을 요소가 없었다. 이 제품의 본질(**자율적으로 일하는
것을 지켜본다**)을 화면 언어로 만든다.

**세 목소리, 세 활자.** 크기만으로 가르면 전부 같은 목소리로 읽힌다.

| 누구의 말 | 활자 | 왜 |
|---|---|---|
| 사람이 친 말 | 산세리프, 13px, 75% | UI 의 목소리 — 내가 넣은 것이지 읽을 것이 아니다 |
| 에이전트의 말 | **세리프(New York), 15.5/1.68** | 읽으라고 있는 문장. 활자가 바뀌는 순간 "누가 말하는지" 가 색·크기 없이 전달된다 |
| 도구 활동 | 고정폭, 11px | 기계가 한 일. 열이 맞아야 훑어진다 |

**서명 — 작업 레일.** 에이전트의 차례는 왼쪽에 가는 선을 세운다. 도구 활동이 그 선에
눈금으로 찍히고, 일하는 동안 **빛이 아래로 흐른다**(차례 길이에 맞춘 거리만큼). 지금 도는
손짓 하나만 맥동하고, 그 아래 경과 시간이 선다. 스피너는 기다림을 말하지만 이 레일은
진행을 말한다 — 이 앱은 기다리는 앱이 아니라 지켜보는 앱이다.

그 밖에

- 시작하는 순간은 **한 덩어리** — 초대 문장 바로 아래에 쓰는 자리. 문장을 위에, 입력을 저
  아래에 두면 화면 가운데가 빈 채로 사람을 기다리게 된다
- 작성창은 여러 줄(⌘↵ 로 보내기) — 에이전트에게 맡기는 일은 한 줄로 끝나지 않는다
- 권한 모드·모델은 **칩**으로 상단에 — 버튼이 아니므로 눌리게 생기지 않는다. 보내기 전에
  "무엇이 일어날지" 를 아는 자리
- 차례가 들어올 때 2px 만 올라온다. 눈이 위치를 다시 찾지 않을 만큼만
- 서브에이전트 타일의 말도 같은 세리프 — 한 화면에 있으므로 같은 목소리다

모든 글자는 여전히 100% currentColor 다. 알파가 걸리는 것은 레일·눈금·칩의 선뿐이다 (§4.2).

## 모델은 서랍에 넣을 것이 아니었다 (2026-08-13, 5차)

지적: "모델 고르기 저따구로 두는 게 맞나". 맞지 않았다.

- **접힌 서랍에 있었다.** 모델은 비용·속도·품질을 한 번에 정하는 1급 선택인데, 권한 모드는
  펼쳐 두고 모델만 "모델 고르기" 버튼 뒤에 숨겼다. 4단계로 꺼내 같은 급으로 세웠다
- **이름만 있었다.** `기본/Opus/Sonnet/Haiku` 로는 무엇을 정하는지 알 수 없다. 각자 한 줄을
  들게 했다 (`가장 똑똑합니다. 느리고 비쌉니다` 등) — 고른 것의 설명이 아래 한 줄로 남는다.
  툴팁에만 두면 마우스를 올리기 전에는 모른다
- **대화 화면의 칩이 눌리지 않았다.** 모델은 대화 중에 가장 자주 바꾸는 것이다. 칩을 눌러
  바로 고르는 작은 판을 열고, 도는 세션이 있으면 "도는 세션은 그대로 — 다음 세션부터" 를
  덧붙인다 (`--model` 은 spawn 인자라 도는 프로세스에 못 건다. 그 사실을 숨기지 않는다)
- 권한 모드 칩은 여전히 사실만 말한다 — 세션의 성격이라 바꾸려면 설정으로 간다

검증: 새 프로필의 첫 화면에 4단계가 서고, 대화 화면에서 칩 → 메뉴 → Haiku 선택 →
저장된 설정이 `haiku` 로 바뀌는 것까지 실기 확인.
