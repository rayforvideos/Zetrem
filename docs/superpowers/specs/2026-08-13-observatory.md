# 5회차 — 터미널 관측기 (orca 방식)

- 작성일: 2026-08-13
- 방향 전환: **입구가 터미널이다.** 앱은 더 이상 에이전트를 띄우지 않는다.

## 왜

클로드 앱식 채팅(앱 안 입력창 → 앱이 headless 를 spawn)은 사람이 이미 살고 있는
자리(터미널)를 두 번째 자리로 만든다. 사람은 터미널에서 `claude` 로 일하고,
Zetrem 은 그 일을 유리 위에 펼치는 **관측기**가 된다.

## 실측 — 기록의 구조 (claude 2.1.229)

```
~/.claude/projects/<프로젝트 경로를 평평하게>/          # / . 공백 _ → 하이픈
  <sessionId>.jsonl                                    # 대화 기록 (append)
  <sessionId>/subagents/agent-<id>.jsonl               # 자식의 기록
  <sessionId>/subagents/agent-<id>.meta.json           # {agentType, description, name, toolUseId, model}
```

- 부모 기록의 `assistant.text` → 1층·전문, `tool_use` → 2층, `Agent` → 자식의 탄생
- 사람이 친 말은 `user.text` — 대화의 절반이라 전문에 남는다
- 자식의 말은 부모 파일에 오지 않는다 (`isSidechain` 은 자식 파일에만 true)
- **자식의 완료는 부모 기록에 문자열 `<task-notification>` 으로 꽂힌다** — `tool-use-id` 로
  meta.json 의 toolUseId 와 이어 붙여 자식 타일을 닫는다

## 설계

- **메인** `session-watcher.ts` — 프로젝트 디렉토리를 400ms 폴링. 새 세션(5분 내 갱신)을
  발견하면 그 시점 크기부터 tail 한다 (지난 대화는 다시 그리지 않는다). 자식 디렉토리도 함께 본다.
  세 이벤트만 렌더러로: `session` · `child` · `lines`
- **순수 파서** `api/claude/transcript.ts` — 기록 한 줄 → 도메인 이벤트. stream-json 파서와
  형태가 달라 별도 모듈이다 (기록에는 queue-operation·ai-title 같은 잡음이 섞인다)
- **관측기** `model/observatory.ts` — 이벤트를 세션 스토어로. React 무지, 화면 없이 테스트
- **화면** 입력창·답하기·권한 승인·끝내기·결과 회수를 **전부 걷어냈다**. 조작의 자리는
  터미널 하나뿐이다. solo 판은 "터미널에서 claude 를 시작하세요" 안내가 된다

## 지운 것

`agent-host.ts`, 러너 레지스트리(`runner.ts`·`runners/*`), stream-json 파서(`parse.ts`),
`use-fleet.ts`, 권한 필드/UI, worktree 격리·결과 회수. spawn 하지 않으므로 전부 존재 이유가 없다.

## 검증 (2026-08-13, 실기)

터미널에서 `claude -p "... Agent 도구로 서브에이전트 ..."` 실행 →
4초에 세션 타일, 10.6초에 자식 타일까지 3분할, 2층에 `Read package.json` · `Agent …` 흐름,
자식 완료 시 알림으로 닫히고 격자가 줄었다. 앱은 아무것도 spawn 하지 않았다.

## 앱 안 터미널 — 입구가 완성됐다 (2026-08-13, 2차)

관측만으로는 반쪽이었다. 사람은 **앱 안에서** `claude` 를 쳐서 시작해야 한다.

- `electron/terminal-host.ts` — `@lydell/node-pty` 로 로그인 셸(PTY)을 띄운다.
  PTY 여야 하는 이유: Claude Code 의 대화형 화면은 TTY 를 요구한다. cwd 는 고른 프로젝트라
  거기서 친 `claude` 가 그 프로젝트의 세션이 되고, 관측기가 그것을 잡는다.
  네이티브 모듈이라 main 번들에서 external 로 뺀다.
- `widgets/terminal` — xterm.js. 배경은 `#00000000` + CSS 세 겹 투명화로 유리에 앉힌다.
- **터미널은 격자의 첫 타일**이다. 세션은 그 옆으로 갈라져 나오고, 터미널 노드는 자리와
  크기만 움직인다 — 다시 마운트하면 셸이 끊겨 그 안의 일이 죽는다. TileDeck 이 이 자리를 보장한다.
- 터미널과 관측기는 서로를 모른다. 그래서 앱 밖 터미널에서 시작한 세션도 똑같이 잡힌다.

검증: 앱 터미널에 CDP 로 실제 키를 쳐서 `claude -p "... Agent 도구로 ..."` 실행 →
7.9초 세션 타일, 14.0초 서브에이전트 타일까지 3분할(터미널 포함 4장), 유리 위 터미널 확인.

## 소유 판정 — 내가 시킨 것만 뜬다 (2026-08-13, 3차)

증상: 앱에서 실행한 적 없는 에이전트의 내용이 타일로 떴다 (사용자 보고). 원인: 관측기가
프로젝트 디렉토리의 **모든** 세션을 잡았다 — 다른 터미널 창의 세션, 다른 도구가 띄운
에이전트까지. 같은 프로젝트에서 여러 세션이 도는 것은 흔한 일이다.

시도하고 버린 것: `lsof -t <기록파일>` 로 붙들고 있는 프로세스를 찾아 셸의 자손인지 보는 법.
**CLI 는 기록에 append 하고 바로 닫는다** (실측: holders 비어 있음). 프로세스 혈통은
살아 있는 파일 핸들이 없어 이어 붙일 수 없다.

채택: **세션 id 를 우리가 발급한다.** 앱 터미널에 `claude` 감싸개를 심어
`--session-id <uuid>` 를 붙이고 그 uuid 를 `userData/terminal-sessions.txt` 에 남긴다.
관측기는 그 목록에 있는 세션만 화면에 올린다. 결정적이고, 기록 포맷에 기대지 않는다.

- 이어가기(`-c`/`-r`)나 사람이 직접 준 `--session-id` 는 감싸개가 손대지 않는다 (CLI 가 거부한다)
- 목록은 터미널이 열릴 때 비운다 — 이 창에서 시작한 것이 이 창의 것이다
- 한계: 감싸개는 셸 함수라 스크립트·서브셸에서 부른 `claude` 는 잡히지 않는다

검증: 같은 프로젝트에서 남의 세션이 활발히 도는 동안 타일 0개 → 앱 터미널에서 `claude` 실행
→ 4초 만에 그 세션만 1개. (`process-tree.ts` 는 혈통 판정이 필요해질 때를 위해 남겨둔다)

## 자식 타일이 비어 있던 이유 (2026-08-13, 4차)

증상: "서브에이전트가 뭐하는지 창에서 하나도 안 나온다".

원인: 파서가 `isSidechain: true` 인 줄을 **무조건** 버렸다. 부모 기록에 자식 말이 섞이는 것을
막으려던 방어인데, **자식 파일의 줄은 전부 사이드체인이라** 같은 파서로 자식 기록을 읽으면
모든 줄이 버려진다. 타일은 뜨지만 내용이 하나도 없었다.

수정: `parseTranscriptLine(line, { sidechain })` — 어느 기록을 읽는지 알려준다.
부모 기록에서는 사이드체인을 버리고, 자식 기록에서는 사이드체인만 취한다. 자식이 받은
일감(문자열 content)도 자식 전문의 첫 줄로 살린다.

검증: 앱 터미널에서 Explore 자식을 띄우니 자식 타일에 1층("I'll help you explore …")과
2층(`Bash find …src/widgets…`)이 흐른다 (스크린샷).

## 끝난 세션이 안 사라지던 이유 (2026-08-13, 5차)

증상: 종료된 세션의 타일이 화면에 남았다.

원인: 자식은 완료 알림으로 닫았지만 **부모 세션에는 끝나는 신호가 없었다.** 기록 파일에도
"끝났다" 는 표시가 없다 (실측: 파일이 그냥 멈춘다).

수정: 우리가 발급한 `--session-id <uuid>` 가 **프로세스 명령줄에 그대로 남는다**(실측).
그래서 2초마다 `ps -eo pid,command` 를 훑어 그 id 가 사라졌으면 종료로 본다 →
`ended` 이벤트 → 그 세션과 **자식들까지** done. 나머지는 기존 경로가 맡는다:
최소 체류시간(4초)을 채운 뒤 물 문법대로 닫히고 스토어에서 걷힌다.

한계: 사람이 인터랙티브 `claude` 를 띄워 두면 프로세스가 살아 있으므로 타일도 계속 있다.
그것이 맞다 — 그 세션은 실제로 살아 있다.

검증: 앱 터미널에서 `claude -p "2+2"` → 타일 등장 → 프로세스 종료 → 4.9초 뒤 타일 소멸.

## 터미널은 우리 것이다 (2026-08-13, 6차)

"순정 터미널을 꼭 써야 하나" — 갈라서 답한다.

- **엔진은 남의 것을 쓴다.** 완전한 VT 에뮬레이션(ANSI·alt 화면·TUI)이 있어야 Claude Code 의
  대화형 화면이 제대로 뜬다. 직접 만들면 그것만 몇 주고, 깨지면 앱의 입구가 깨진다.
- **표면은 우리 것이다.** 순정으로 보이던 것은 xterm 기본값을 쓰고 있었기 때문이다.

`widgets/terminal/lib/theme.ts` — 팔레트를 유리 틴트에서 파생한다.

- 배경은 칠하지 않는다(유리의 몫), 글자·커서·선택은 `tint.text` 에서 나온다 — 새 색을 안 들인다
- **ANSI 팔레트를 두 벌 둔다.** 순정 팔레트는 검은 배경 전제라 밝은 유리 위에서 노랑·청록이
  사라진다. 극성을 따라 고르고, **§4.2 의 4.5:1 을 테스트가 지킨다** (여섯 색 × 두 극성)
- 커서는 얇은 막대(블록은 유리 위에서 구멍처럼 보인다), 부드러운 스크롤, 초점 링
- 머리글은 세션 타일과 같은 문법: 이름("터미널") + 종류(현재 경로)

검증: `git status`·`ls -G` 색상이 유리 위에서 읽히고, 그 아래로 세션·자식 타일이 갈라진다 (스크린샷).

## 배치를 다시 잡다 (2026-08-13, 7차 — "UI 진짜 구리다")

증상이 맞았다. 타일 셋이 화면을 똑같이 나눠 갖는데 내용은 두 줄뿐이라 **텅 빈 회색 판**이
셋 놓인 그림이었다. 격자가 모든 타일을 동등하게 대한 것이 원인이다 — 그런데 이 화면에서
동등하지 않다: **일하는 자리는 터미널 하나**이고 세션 타일은 지켜보는 판이다.

`observatoryLayout` (TDD):

- 터미널이 왼쪽 기둥(가로 52% — 셸 80칸이 접히지 않는 폭), 세로로 꽉 참
- 세션은 오른쪽에 쌓인다. 넷을 넘으면 두 줄로 접어 판이 우표만 해지지 않게 한다
- 세션이 없으면 터미널이 화면을 갖는다

타일 안쪽도 다시 짰다.

- 머리글에 **상태 점** — 작업 중은 맥동, 대기는 빈 고리, 끝난 것은 잔잔한 점. 색은 안 들인다
- 1층은 3줄에서 자른다(타일은 문서가 아니라 상태판), 2층은 바닥에 붙어 흐른다
- **3층을 오른쪽 위로 옮겼다** — 아래에 두니 왼쪽에서 흘러온 2층과 같은 줄에서 겹쳤다
- 유리 테두리를 흰 선에서 `currentColor` 혼합으로 (밝은 유리에서 흰 선은 사라진다)

## 전경 자식이 안 닫히던 이유 (같은 회차)

증상: "서브 에이전트 또 안 꺼진다". 백그라운드 자식은 `<task-notification>` 으로 닫았지만
**전경 자식은 그 알림을 내지 않는다** — 부모 기록에 `tool_result` 로만 끝난다. 파서가 그걸
무시하고 있었다. 이제 부모 기록의 tool_result 도 `childClosed` 로 낸다 (관측기가 아는
자식 id 만 닫으므로 다른 도구의 결과는 그냥 지나간다).

검증: 병렬 자식 둘 → 터미널 곁에 두 판으로 뜨고, 각자 끝나며 닫혀 타일 0으로 돌아왔다.

## 자식의 수명은 자기 것이다 (2026-08-13, 8차 — 아키텍처 수정)

증상이 반복됐다: 자식 타일이 끝나도 남는다. 신호를 하나씩 덧대는 것으로는 끝나지 않았다.

**근본 원인 — 자식의 생사를 남의 기록으로 판정했다.** 지금까지 자식 타일은 부모 기록의
신호(`<task-notification>` 또는 그 자식의 `tool_result`)로 닫혔다. 그 구조에는 실패 경로가
여럿이다: ① 우리가 tail 을 시작하기 전에 그 줄이 쓰였으면 영영 못 본다 ② meta.json 의
`toolUseId` 로 이어 붙이는 데 실패하면 못 닫는다 ③ 전경·백그라운드가 서로 다른 신호를 낸다.
셋 다 "타일이 남는다" 로 끝난다.

**수정 — 각 타일의 수명을 자기 기록에서 읽는다.**

| 타일 | 살아 있음의 근거 |
|---|---|
| 세션(부모) | 그 `--session-id` 를 단 프로세스가 있다 (`ps`) |
| 자식 | 자기 기록의 마지막 말이 `stop_reason: end_turn` 이다 |

자식은 한 번 답하고 끝나므로 end_turn 이 곧 그 수명의 끝이다 (실측: 자식 파일 셋 모두
마지막 줄이 `stop_reason=end_turn`). 부모는 다르다 — 사람이 다음 말을 칠 수 있으므로
턴이 끝나도 세션은 살아 있다. 그래서 부모의 근거는 프로세스다.

부모 기록의 신호들은 남겨 두되 이제 보조다. 부모가 죽으면 자식도 함께 거두는 것도 그대로다.

검증: 자식 둘이 19.5초·20.3초에 뜨고 **47.6초에 스스로 닫혔다 — 그때 부모는 여전히 working**.

## 유리를 유리로 (2026-08-13, 9차 — "그냥 흰색 창")

증상: 유리가 우윳빛 판이었다. 원인은 **보증을 알파로 지고 있었기 때문**이다 —
4.5:1 을 표면 전체의 불투명도로 만들면, 사진이 복잡할수록 알파가 올라가 판이 배경을 덮는다.

시도하고 버린 것: **글자 뒤에만 판을 까는 방법.** 표면은 얇게 두고 보증을 국소화하는
발상은 맞지만, 화면에서는 흐릿한 얼룩 덩어리가 됐다 — 타일 안에서 밀도가 자리마다 달라
"판이 하나" 라는 인상이 깨진다. 유리는 **한 겹으로 균일해야** 한다.

채택: 보증은 표면이 지되(균일), **유리의 인상은 알파가 아닌 곳에서 만든다.**

- 블러 24 → 32px (44 는 배경을 죽처럼 뭉갰다)
- `saturate(1.3)` — 블러만 걸면 색이 회색으로 주저앉아 안개가 된다. 1.8 은 초록이 번졌다
- 위 모서리에 반짝(0.35), 아래 모서리에 그늘, 바닥으로 떨어지는 그림자 — 유리판의 두께
- 알파 상한 0.85 → 0.62, 기본 두께 0.5 → 0.25
- 터미널 안의 초점 링 제거 — 유리 타일 안에 액자가 한 겹 더 생겨 무엇이 판이고 무엇이
  내용인지 흐려진다. 초점은 깜빡이는 커서가 이미 말한다

대비 보증은 그대로다 (테스트 24개, 밝기 범위 쌍 × 두께 전 조합).

## 앱이 물려준 환경이 기록을 껐다 (2026-08-13, 10차 — 치명)

사용자 화면에 `Transcript saving is off — inherited CLAUDE_CODE_CHILD_SESSION marker` 가 떴다.
Zetrem 자체가 Claude Code 안에서 돌면(개발 중에는 늘 그렇다) 앱의 환경에 그 표식이 실리고,
PTY 가 그대로 물려받아 **터미널에서 띄운 claude 가 기록을 남기지 않는다** — 관측기가 눈을 잃는다.
`cleanShellEnv` 로 `CLAUDECODE`·`CLAUDE_*` 를 걷어낸다. 인증(`ANTHROPIC_*`)은 남긴다.

## 이 터미널의 에이전트에게 이름을 준다 (같은 회차)

같은 `claude` 라도 Zetrem 에서 띄운 것은 이 책상의 식구다. 셸의 감싸개가 우리 것을 붙인다:

- `--settings` — 상태줄을 우리 문법으로: `◆ Zeta  <모델>  <디렉토리>  ⎇ <브랜치>`
- `--append-system-prompt` — 답의 첫 줄이 곧 타일의 1층이 되도록, 서브에이전트 description 은
  사람이 읽을 이름으로 짓도록
- 타일의 이름도 `Zeta <id앞4>` 로 선다 — 화면과 터미널이 같은 이름을 부른다

CLI 의 환영 배너는 CLI 의 것이라 지우지 않는다. 사람이 오래 보는 것(상태줄·말투·타일 이름)이
우리 것이면 충분하다.

## 유리 액자가 화면을 감싼다 (같은 회차)

터미널만은 반투명 위에 둘 수 없다. 남이 그리는 화면이라 희미한 안내·8색 팔레트·박스 그림의
대비를 우리가 못 정하고, 실제로 claude 환영 배너가 씻겼다. 그래서 **그 자리만 바닥을 깐다**
(표면색 88%) — 유리는 둘레(패딩·머리글·모서리·그림자)에서 보인다. 예쁘기 전에 읽혀야 한다.
