# 3회차 마무리 — 멀티턴 히스토리 (대화 전문)

- 작성일: 2026-08-13
- 2회차 스펙이 "다음 회차"로 미룬 셋(권한 중계·worktree 격리·멀티턴 히스토리) 중 마지막.

## 문제

대기 타일의 1층 headline 은 140자 요약이다. 에이전트가 실제로 물은 것을 읽을 수 없으면
답 창구(자유 문장)도 권한 창구(허용/거부)도 장님 승인이 된다.

## 설계

- **모델** 세션에 `transcript: TranscriptEntry[]` (`{role: user|assistant, text}`, 상한 200).
  headline 은 "지금 읽을 한 줄", transcript 는 잘리지 않은 원문 — 같은 말이 두 자리로 간다.
- **창구** `RunSink.message(role, text)`. claude 러너는 시작 프롬프트·assistant text 원문·
  send 답을 흘리고, fake 러너도 같은 리듬을 빌린다(데모에서 전문 UI 가 보여야 한다).
- **UI** 전문은 **시선의 주인이 된 대기 타일에서만** 펼쳐진다 (스펙 §6 — 읽는 자리는
  대기가 만든다). 펼쳐지면 1층 요약 문장은 물러난다(정체성은 남는다). 권한 질문과는
  공존한다 — 맥락 없이 승인할 수 없다. 스크롤 문서이고 애니메이션은 없다 (스펙 §3).
  사람의 말은 색이 아니라 왼쪽 선과 들여쓰기로 가른다 — 대비 보증을 깎지 않는다 (§5.1).

## 검증 (2026-08-13, CDP 실기)

"색을 물어봐" 시나리오: 실행 → waiting 에서 전문에 프롬프트+질문 원문 → "청록색" 답 →
후속 턴의 "청록" 까지 한 타일에 이어짐. 1층 요약과 전문의 중복 0. 스크린샷으로 유리 확인.
