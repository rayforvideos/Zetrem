# 4회차 — 작업 결과 회수와 세션 끝내기

- 작성일: 2026-08-13

## 문제 둘

1. **일의 행방이 화면에 없다.** 에이전트가 worktree 에 커밋을 남겨도 타일은 조용히 닫히고
   브랜치만 남는다. 병합은 사람의 일이지만, 일이 어디 있는지는 화면이 말해야 한다.
2. **done 에 이르는 사람의 길이 없다.** headless 프로세스는 일을 마쳐도 스스로 끝나지 않고
   waiting 으로 다음 입력을 기다린다 — 실기에서 발견. 세션을 끝낼 창구가 없으면
   결과 회수는 영원히 트리거되지 않는다.

## 설계

- **메인** 종료 시 worktree 를 검사(`inspectWorkspace`: 커밋 수 + 미커밋 파일 수)해서
  남은 게 있으면 `outcome` 이벤트를 **exit 보다 먼저** 보낸다 — exit 이 도착하면 렌더러가
  구독을 끊으므로 순서가 계약이다. 깨끗하면 기존처럼 치운다. 검사 실패(null)는 0 과
  다르다 — 모르는 것을 지우면 안 된다.
- **러너** `stop()` 은 kill 을 요청하고 **퇴장을 기다린다**. 즉시 done 을 찍고 구독을 끊던
  이전 의미는 outcome 을 유실한다. done 은 exit 핸들러가 찍는다.
- **세션** `outcome?: WorkOutcome { branch, commits, dirtyFiles }`.
- **UI**
  - 대기 타일(시선의 주인)의 답 창구 옆에 **끝내기** — done 에 이르는 사람의 길.
  - 결과를 남기고 끝난 타일은 **자동으로 닫히지 않고** 브랜치 원문·커밋·미커밋 수를
    보여준다. **닫기**는 사람이 누른다. 결과 없이 끝나면 기존처럼 스스로 닫힌다.

## 검증 (2026-08-13, CDP 실기)

"파일 만들어 커밋해줘" → Write·Bash 권한 허용 → waiting → 끝내기 → 결과 타일
`zetrem/claude-0-… 커밋 1 · 미커밋 0` → 닫기 → 타일 0. 브랜치에 커밋이 실제로 남아 있었다.
