# shadcn/ui 셋업 — 유리가 토큰을 구동한다

- 작성일: 2026-08-13

## 무엇을 넣었나

- `tailwindcss@4` + `@tailwindcss/vite` (electron-vite 의 renderer 플러그인에 추가)
- shadcn CLI 로 받은 컴포넌트 7개: `button` `card` `dropdown-menu` `textarea` `badge`
  `separator` `scroll-area` → `src/shared/ui/` (FSD 의 shared 레이어가 그 자리다)
- `components.json` — 다음부터 `npx shadcn@latest add <이름>` 이 이 규칙대로 놓는다
  (별칭: components·ui → `@/shared/ui`, utils → `@/shared/lib/cn`)
- `cn()` (clsx + tailwind-merge)

## 핵심 — 색을 고정하지 않는다

shadcn 은 `--background`·`--foreground`·`--primary` 같은 토큰 위에 서고, 보통 그 값은
라이트/다크 두 벌로 **고정**된다. 이 앱에서는 고정될 수 없다: 색은 배경 사진의 밝기에서 매 순간
계산되고, 4.5:1 보증이 그 계산에 걸려 있다 (스펙 §4.1·§4.2).

그래서 `@theme inline` 이 우리 변수를 shadcn 토큰의 **소스**로 쓴다:

```
유리 틴트 → --zt-text / --zt-on-primary → --color-foreground / --color-primary /
                                          --color-border / --color-muted-foreground …
```

모든 토큰은 `currentColor`(=틴트가 보증한 글자색)의 파생이다 — 색을 새로 들이지 않는다.
그래서 shadcn 컴포넌트를 그대로 쓰면서도 배경을 바꾸면 극성이 뒤집히고 보증이 따라온다.

## 두 번 물린 자리

1. **레이어.** Tailwind v4 유틸리티는 `@layer utilities` 에 산다. 레이어 **밖**의 규칙은
   레이어 안의 것을 언제나 이기므로, 우리가 쓰던 `* { margin: 0 }` 하나가 `mr-auto` 같은
   유틸리티를 전부 죽였다 (실측: 머리글 칩이 오른쪽으로 안 밀렸다). 우리 CSS 를
   `@layer base` 로 내려 해결.
2. **포털.** Radix 는 메뉴를 `body` 로 포털한다 — 유리 판 바깥이라 판에 걸어둔 `--zt-*` 를
   못 받고 토큰이 전부 기본색으로 떨어진다. 대화 판의 틴트를 문서 뿌리에도 심고,
   떠 있는 판은 스스로 배경을 흐리게 했다 (유리 위에 뜬 것도 유리여야 한다).

## 남긴 것

`.zt-rail`·`.zt-tick`·`.zt-enter`·`.zt-scroll` 은 그대로 둔다 — 이 앱의 서명(작업 레일)과
물 문법은 shadcn 이 주지 않는 것이고, Tailwind 유틸리티로 표현하면 의미가 클래스 이름에서
사라진다.

검증: 실기에서 `보내기` 버튼의 계산된 배경이 틴트 글자색(rgb(11,12,14)), 글자가 표면색
(rgb(246,247,250))으로 나왔고, 모델 메뉴가 유리 위에 떠서 열렸다 (스크린샷).
